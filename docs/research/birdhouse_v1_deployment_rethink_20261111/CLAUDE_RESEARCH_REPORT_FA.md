# Birdhouse روی Grove Vision AI V1 — ارزیابی مستقل معماری استقرار

تاریخ: 2026-11-11. نویسنده: Claude (بازبینی مستقل). این سند فقط حاصل پژوهش است؛
در تهیهٔ آن هیچ چیزی build، flash یا reset نشد و هیچ داده‌ای به برد فرستاده نشد.
نسخهٔ انگلیسی: `CLAUDE_RESEARCH_REPORT.md` (در صورت اختلاف، نسخهٔ انگلیسی ملاک است).

برچسب‌های وضعیت:

- **VERIFIED** — خودم روی خودِ artefact (سورس، object code، باینری، لاگ) بررسی کرده‌ام.
- **PLAUSIBLE** — شواهد سازگار است ولی اثبات نشده.
- **UNVERIFIED** — هنوز شاهدی وجود ندارد.
- **NOT SUPPORTED** — شواهد علیه آن است.

مسیرها نسبت به ریشهٔ مخزن هستند. پوشهٔ `.local-tools/` منتشر نمی‌شود (SDK سازنده، toolchain،
خروجی build و لاگ‌های تشخیصی).

## ۱. حکم مستقل

1. **ELF مرحلهٔ ۵۰ نمی‌تواند مدل را اجرا کند و نباید flash شود.** VERIFIED.
   build سازندهٔ TFLite Micro برای مدل دوربینِ همراهش، kernelها را به تفکیک نوع داده غیرفعال می‌کند
   و INT8 `FULLY_CONNECTED` در فهرست غیرفعال‌هاست. در object کامپایل‌شده، `Eval` این kernel یک
   stub چهل‌وشش‌بایتی است که خطا برمی‌گرداند و `Prepare` هم برای حالت MLI خطا می‌دهد؛ لایهٔ Dense
   آخر مدل دقیقاً همین حالت است، پس `AllocateTensors` در شروع شکست می‌خورد. firmware بدون خطا
   link می‌شود و هیچ تست host روی preprocessing یا صف نمی‌توانست این را آشکار کند.
2. **هیچ firmware آماده‌ای این pipeline را اجرا نمی‌کند.** VERIFIED. firmware کارخانهٔ Seeed
   مسیر صوتی ندارد. firmware آمادهٔ Edge Impulse ضبط را به حدود ۴ ثانیه و inference را به ۲٫۰۵ ثانیه
   محدود می‌کند. برای inference روی خود تراشه، یک بار نوشتن firmware روی Himax اجتناب‌ناپذیر است.
3. **طراحی صف streaming روی این تراشه لازم نیست.** حدود ۸۴۰ کیلوبایت RAM آزاد است. کپی نمونه‌ها
   در callback صوتی به یک بافر خطی و پردازش بعد از آن، همان الگوی خود سازنده است و از preprocessing
   دسته‌ای استفاده می‌کند که روی host با Python تطابق کامل داشت.
4. **رفتار کتابخانهٔ صوتیِ از‌پیش‌کامپایل‌شده با فرض کد فرق دارد.** VERIFIED با disassembly:
   callback در context وقفه اجرا می‌شود، هر بلوک در نرم‌افزار دوباره arm می‌شود، و overrun و
   سرریز FIFO بی‌صدا مدیریت می‌شوند.
5. **مجهول‌هایی که فقط سخت‌افزار جواب می‌دهد:** پیوستگی PDM، کلاک واقعی CPU، زمان inference،
   رفتار انتقال روی این PC، و اینکه امروز چه برنامه‌ای روی برد نصب است.

## ۲. سیستم واقعی

```
 Linux PC ──USB── BL702 (flash مستقل، بازیابی با mask ROM)
                   │  حالت bootloader  2886:0060: TinyUF2 (CDC + mass storage)
                   │  حالت عادی        2886:8060: پل CDC به UART تراشهٔ Himax
                   │
                   ├─UART ── XMODEM ──► bootloader مرحلهٔ اول Himax ─► نوشتن flash   [اتصال: PLAUSIBLE]
                   ├─I2C، HX_RST، دو خط GPIO
                   └─SPI از طریق سوئیچ آنالوگ ──► P25Q32SH خارجی، ۴ مگابایت          [VERIFIED]
                                                  slotهای مدل در 0x30000000 + n·1MB
 Himax HX6537-A (ARC EM9D، FPU تک‌دقت سخت‌افزاری، برنامه از RAM اجرا می‌شود)
   تصویر flash دو مگابایتی: 2nd bootloader @0x0 · bootloader @0x10000 · layout @0x20000
                            loader config @0x21000 · application @0x22000
   RAM: ICCM1 320KB کد · BOOT 130KB · SYSTEM0 1406KB · DCCM 248KB + stack هشت‌کیلوبایتی
   میکروفون PDM مدل MSM261D3526H1CPM ── کتابخانهٔ صوتی prebuilt (بدون سورس)
   Grove I2C ── I2C slave تراشهٔ Himax ◄── میزبان سازگار با Arduino برای روش تعمیر مستند   [آزمایش‌نشده]
 JTAG: شاهدی از پین در دسترس نیست. بوت ROM از I2C فقط وقتی bootloader روی flash نباشد یا
 نامعتبر باشد؛ تصویر حداکثر ۱۲۸ کیلوبایت و امضاشده.
```

## ۵. طرح‌های رتبه‌بندی‌شده

1. **برنامهٔ Edge Impulse سازنده دست‌نخورده به‌علاوهٔ یک ماژول مجزای Birdhouse** که با فرمان کنسول
   فعال می‌شود: capture-then-process، مدل کامپایل‌شده در firmware، فعال‌سازی kernelهای INT8، arena
   بزرگ‌تر، تشخیص dropout در سطح برنامه و diagnosticهایی که بازمحاسبهٔ نتیجه روی host را ممکن می‌کند.
2. **fork کوچک‌شدهٔ سازنده** با حفظ کنسول AT.
3. **برنامهٔ اختصاصی حداقلی** روی همان SDK.

رد شده‌ها: مرحلهٔ ۵۰ به همین شکل، فقط‌مدل روی firmware کارخانه، impulse بومی برای این مدل،
inference روی host، اجرا از RAM، سخت‌افزار دیگر.

## ۶. ممیزی خصمانهٔ کد مرحلهٔ ۵۰

- **stub بودن عملگر (بحرانی).** بخش ۱ را ببینید.
- **Arena.** صدوشصت کیلوبایت هرگز اجرا نشده بود؛ فقط activationها حدود ۱۴۰ کیلوبایت‌اند.
- **adapter در برابر رفتار واقعی کتابخانه.** منطق wrap و بررسی «available > block count»
  دست‌نیافتنی است. adapter برای گزارش dropout به کتابخانه تکیه می‌کرد که هرگز گزارش نمی‌دهد.
- **stop و شروع دوباره.** اگر `stop` شکست بخورد، پرچم «started» می‌ماند و همهٔ شروع‌های بعدی رد می‌شوند.
- **مدل real-time.** قید اصلی hop بیست‌میلی‌ثانیه‌ای نیست؛ تأخیر وقفه در مرز هر بلوک است.
- **timeout.** به ساعتی تکیه دارد که می‌تواند یک ثانیه بپرد؛ برای timeout بی‌خطر، برای اندازه‌گیری زمان مضر.
- **عددی.** تطابق روی host با کتابخانهٔ ریاضی host بود؛ روی ARC تفاوت ±۱ در ویژگی‌های INT8 ممکن است.
- **packaging.** مرحلهٔ تولید و امضای تصویر هرگز برای مرحلهٔ ۵۰ اجرا نشده بود.
- **آنچه تست offline نشان نمی‌دهد:** پیوستگی و بهرهٔ PDM، نرخ نمونه‌برداری واقعی، رفتار وقفه
  هنگام inference، زمان inference، عمق stack، تطابق عددی MLI.

## ۷. گردآوری شواهد با کمترین ریسک (فقط خواندنی)

بدون برد، قابل تکرار:

```
arc-elf32-nm -S -C <build مرحلهٔ ۵۰>/.../kernels/fully_connected.o
arc-elf32-objdump -d --start-address=0x100225d4 --stop-address=0x1002293a <ELF مرحلهٔ ۵۰>
sha256sum grove_ai_v02-00.uf2    # 8854e093…5b3c
```

با برد متصل و فقط مشاهده (هر مورد نیازمند تأیید مالک؛ خودِ اتصال برد باعث probe سیستم‌عامل می‌شود):
مقدار `idProduct` در sysfs (‏`8060` حالت عادی، `0060` bootloader)؛ `udevadm info` روی پورت سریال
برای اینکه آیا ModemManager آن را probe می‌کند؛ لاگ کرنل هنگام attach؛ ضبط غیرفعال با `usbmon`.

درخت تصمیم: attach سالم با automount خاموش ← انتقال mass storage قابل استفاده؛ هنگ مرتبط با
MODE SENSE ← امتحان با quirk؛ همچنان ناپایدار ← بررسی XMODEM مستقیم؛ به‌روزرسانی bootloader فقط
اگر هیچ‌کدام جواب نداد.

## ۸. دروازه‌های GO/NO-GO برای هر نوشتن سخت‌افزاری

- **G1** برنامهٔ نصب‌شده شناسایی شده و مالک تصمیم گرفته چه چیزی باید قابل حفظ باشد.
- **G2** بررسی‌های offline قبول شده: ممیزی عملگرها، inference روی host با همان سورس‌های TFLM،
  packaging، یکسانی ناحیه‌های bootloader با تصویر کارخانه، آدرس‌های UF2 در بازهٔ مجاز.
- **G3** یک روش انتقال، تمرین بدون نوشتن را گذرانده است.
- **G4** کیت بازیابی آماده است.
- **G5** پورت USB مستقیم، تغذیهٔ پایدار، بدون فرایند دیگری روی پورت سریال.
- **G6** تأیید صریح مالک.

تصویر کارخانه و تصویر Edge Impulse راه برگشت‌اند، نه backup این برد.

## ۹. ادعاهایی برای چالش مستقل

1. `fully_connected.o` مرحلهٔ ۵۰ یک `Eval` چهل‌وشش‌بایتی دارد که ۱ برمی‌گرداند.
2. در `hx_lib_audio_start` تعداد بلوک بیش از ۵۰ CPU را halt می‌کند و فاصلهٔ آدرس بلوک‌ها `block_sz` بایت است.
3. callback صوتی برنامه داخل `pdm_rx0_rx_ISR` و پیش از پاک شدن وقفهٔ DMA اجرا می‌شود.
4. هنگام overrun، کتابخانه هر دو index را صفر می‌کند و چیزی به برنامه گزارش نمی‌دهد.
5. ناحیهٔ 0x0–0x20000 در `grove_ai_v02-00.uf2`، `firmware.uf2` و باینری‌های SDK بایت‌به‌بایت یکسان است.
6. firmware آمادهٔ Edge Impulse بدون تغییر سورس برای پنجرهٔ ۸۰٬۰۰۰ نمونه‌ای ساخته نمی‌شود.
7. `grove_ai_v02-00.uf2` هیچ مسیر کد صوتی، PDM یا میکروفون ندارد.
8. bootloader نسخهٔ v2.0.1 فایل `CURRENT.UF2` ارائه نمی‌کند.
9. اوج حافظهٔ activation مدل ۱۴۰٬۰۰۰ بایت است (با فرض SAME padding).
10. طراحی دو‌بافری بدون DSP به‌صورت streaming پنجره‌های پنج‌ثانیه‌ای بدون وقفه می‌دهد، به شرط اینکه پردازش کمتر از ۵ ثانیه طول بکشد.

## محدودیت‌ها

- مسیر نوشتن firmware از BL702 به Himax از دو سر آن استنباط شده، نه از سورس.
- تحلیل BL702 روی باینری v2.0.1 انجام شد، نه نسخهٔ نصب‌شده روی برد.
- همهٔ اعداد زمانی تخمین‌اند.
- روش‌های بازیابی را سازنده‌ها مستند کرده‌اند ولی اینجا آزمایش نشده‌اند.
